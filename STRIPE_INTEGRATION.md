# Интеграция Stripe в Eng-Landia

## Обзор

Интеграция Stripe позволяет автоматически отправлять предложения подписки студентам после завершения первого урока и обрабатывать платежи через Stripe Checkout.

## ⚠️ Важно: Диагностика проблем

### Проблема: Email приходит без кнопок оплаты

Если вы получаете email с предложением подписки, но в нем нет кнопок для оплаты, это означает, что ссылки на Stripe не создаются.

**Возможные причины:**
1. Не настроены переменные окружения Stripe
2. Неправильные Price IDs
3. Ошибка в Stripe API

**Решение:**
1. Перейдите на `/stripe-setup` для пошаговой настройки
2. Используйте `/test-stripe-links` для диагностики
3. Проверьте консоль сервера на наличие ошибок

## Установленные зависимости

```bash
bun add stripe @stripe/stripe-js
```

## Структура интеграции

### 1. Конфигурация Stripe (`src/lib/stripe.ts`)

- Инициализация Stripe клиента
- Конфигурация типов подписок (Базовый: 4 урока/мес, Интенсивный: 8 уроков/мес)
- Экспорт функций для работы с Stripe

### 2. API Endpoints

#### `/api/subscription/create-checkout` (POST)
- Создает Stripe Checkout Session для подписки
- Принимает `subscriptionType` и `userId`
- Возвращает URL для оплаты

#### `/api/webhooks/stripe` (POST)
- Обрабатывает webhook события от Stripe
- Автоматически изменяет роль пользователя при успешной оплате
- Обрабатывает отмену и неудачные платежи

#### `/api/debug/test-subscription-email` (POST)
- Тестирует функцию отправки email с подпиской
- Показывает детальную информацию о создании ссылок

#### `/test-user-role-change`
- Тестирование изменения ролей пользователей
- Симуляция webhook событий
- Ручное изменение ролей для тестирования

### 3. Email интеграция

Обновлен `src/server/registration/subscription-email.ts`:
- Автоматически генерирует ссылки на Stripe для каждого типа подписки
- Отправляет email с кнопками для оформления подписки
- Работает в режиме разработки (выводит данные в консоль)
- **Показывает предупреждения, если ссылки не создаются**

### 4. Страницы

#### `/subscription/success`
- Страница успешной оплаты
- Показывает информацию о активированной подписке

#### `/subscription/cancel`
- Страница отмененной оплаты
- Объясняет что произошло и что делать дальше

#### `/stripe-setup`
- Пошаговая инструкция по настройке Stripe
- Список всех необходимых переменных окружения

#### `/test-stripe-links`
- Диагностика создания ссылок на Stripe
- Тестирование email функции

### 5. Модалки

#### `SubscriptionSuccessModal`
- Модалка успешной оплаты
- Показывается при возврате с успешной оплаты

#### `SubscriptionCancelModal`
- Модалка отмененной оплаты
- Показывается при отмене оплаты

## Переменные окружения

Добавьте в `.env.local`:

```env
# Stripe Keys
STRIPE_SECRET_KEY=sk_test_...
STRIPE_PUBLISHABLE_KEY=pk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...

# Stripe Price IDs (создайте в Stripe Dashboard)
STRIPE_BASIC_PRICE_ID=price_...
STRIPE_INTENSIVE_PRICE_ID=price_...

# Домен для redirect URLs
NEXT_PUBLIC_DOMAIN=http://localhost:3000
```

## Настройка Stripe

### 1. Создание продуктов и цен

В Stripe Dashboard создайте:

1. **Продукт "Базовый план"**
   - Название: "Базовый план"
   - Описание: "4 урока в месяц"
   - Создайте цену с рекуррентной оплатой

2. **Продукт "Интенсивный план"**
   - Название: "Интенсивный план"
   - Описание: "8 уроков в месяц"
   - Создайте цену с рекуррентной оплатой

### 2. Настройка Webhook

В Stripe Dashboard:

1. Перейдите в Webhooks
2. Создайте endpoint: `https://your-domain.com/api/webhooks/stripe`
3. Выберите события:
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.payment_failed`
4. Скопируйте webhook secret в переменную окружения

## Логика работы

### 1. Отправка предложения подписки

После того как учитель отмечает посещение первого урока:

1. Система проверяет, что это первый урок студента
2. **Генерирует ссылки на Stripe для каждого типа подписки**
3. Отправляет email с предложением подписки
4. Email содержит кнопки для оформления подписки

### 2. Обработка оплаты

1. Студент кликает на ссылку в email
2. Перенаправляется на Stripe Checkout
3. После оплаты перенаправляется на `/subscription/success`
4. Webhook обрабатывает событие и изменяет роль пользователя

### 3. Управление подписками

- **Активация**: Роль изменяется с 'guest' на 'student'
- **Отмена**: Роль возвращается к 'guest'
- **Неудачный платеж**: Роль остается 'guest'

## Тестирование

### Тестовая страница

Перейдите на `/test-stripe` для тестирования:
- Модалок успешной и отмененной оплаты
- Проверки конфигурации

### Диагностика ссылок

Перейдите на `/test-stripe-links` для:
- Тестирования создания ссылок на Stripe
- Проверки переменных окружения
- Диагностики email функции

### Тестирование изменения ролей

Перейдите на `/test-user-role-change` для:
- Просмотра всех пользователей с их ролями
- Ручного изменения ролей для тестирования
- Симуляции webhook событий Stripe
- Проверки логики изменения ролей

**Поддерживаемые симуляции:**
- `checkout.session.completed` - успешная оплата (guest → student)
- `customer.subscription.canceled` - отмена подписки (student → guest)
- `customer.subscription.deleted` - удаление подписки (student → guest)

### Тест webhook

Используйте Stripe CLI для тестирования webhook:

```bash
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```

### Тест email

В режиме разработки email не отправляется, а данные выводятся в консоль.

**Важно:** Проверьте консоль сервера на наличие предупреждений о том, что ссылки не создаются.

## Безопасность

- Все платежи обрабатываются через Stripe
- Webhook подписывается для проверки подлинности
- Метаданные содержат userId для связи с пользователем
- Роли пользователей проверяются перед созданием подписки

## Мониторинг

Логи webhook событий:
- Успешные платежи
- Отмены подписок
- Неудачные платежи
- Изменения ролей пользователей

**Логи создания ссылок:**
- Успешное создание ссылок на Stripe
- Ошибки при создании ссылок
- Отсутствие переменных окружения
